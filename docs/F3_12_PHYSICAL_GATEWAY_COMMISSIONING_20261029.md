# F3.12 — Commissioning genuine RFID/barcode gateway evidence
Author: Sunil Jain, CyberinQ LLC, 2026-10-29

## Status and what this adds

This increment **does not claim physical hardware was tested**. It provides reproducible tools for a witnessed commissioning run using a **real gateway-signed F3.3 WIP scan**, the **existing F3.11 durable relay receipt**, and the **actual PostgreSQL 16 F3.3 record**. It adds `scanrelay verify`, `scanrelay audit`, a read-only database audit and an operator runbook. No migration, fake production events, new scanner enrollment, new privileges, new signer, new work completion, or custody mutation.

F3.11 must first be installed and Git-committed. The last confirmed server baseline is F3.10 commit `c33a614`; **F3.11 installation has not been confirmed**. This ZIP intentionally **does not contain** F3.11's new `scanrelay/main_test.go` or original `scanrelay/main.go` baseline; it modifies F3.11's `main.go` and adds companion files. Install in sequence.

## Admission and evidence boundaries

1. The scanner gateway (not this tool) reads the physical carrier and its **enrolled** signer generates a `WIP_GATEWAY_SCAN_V1` envelope. Preserve the original signature and observation timestamp. `scanrelay verify` validates syntax, the exact F3.3 newline-delimited Ed25519 signature, independently supplied tenant/plant/gateway/station and acceptable future clock drift. It computes the same `event_sha256` and `signature_sha256` used by F3.3. The provided public key is not yet proven enrolled until the database check.
2. F3.11 `enqueue` safely persists the signed envelope before a gateway process reports local queue acceptance. F3.11 `flush` sends it over approved TLS to the existing F3.3 POST endpoint. Never enable an HTTP endpoint or disable certificate verification. F3.3 validates enrolled key, accepted cutting part, active RFID binding, 15-minute default age window, and gateway event ID replay/conflict protection. It issues a signed-source **report**, not sensor-guaranteed physical presence.
3. `scanrelay audit` verifies the retained accepted receipt for the **exact envelope SHA-256** and checks the scan UUID. This step sends **no network requests** and makes **no PostgreSQL writes**. The receipt is a local server-reported acknowledgement, not independently sufficient evidence.
4. `scripts/test_wip_f312_live_pg.sql` runs inside `BEGIN READ ONLY`, sets `ROLE agiparel_app`, enforces the expected `app.current_tenant_id`, and compares enrolled key, tenant, plant, gateway, station, event ID, part, carrier, EPC, recorded event and signature hashes, and the accepted scan UUID against the immutable row. A replay is the **same** row, not an additional scan. Movement count and unresolved exception count are displayed **as observations**, never treated as an automatic approval to ship or bypass a hold.

## Prerequisites and exact commands (real staging hardware only)

Provision an actual F3.3 gateway in staging, approved fabric cutting part and carrier binding, a working signer, a trusted HTTPS ingress and synchronized clocks. Independently obtain the **enrolled Ed25519 public key** (64 hex characters) and the expected scope from the gateway provisioner, not from the envelope under test. Staging credentials are not generated by this tool.

From repo root (build after installing this ZIP):

```sh
mkdir -p "$HOME/bin"
go build -o "$HOME/bin/agiparel-scanrelay" ./services/edge-daemon/cmd/scanrelay

# Fill with actual accepted factory identities; never create synthetic event IDs.
export F312_FILE="/secure/scanner/genuine-signed-scan.json"
export F312_DIR="$HOME/.local/share/agiparel-scan-outbox"
export F312_PUBLIC_KEY_HEX="<actual enrolled public key, hex>"
export F312_TENANT="<actual tenant code>"
export F312_PLANT="<actual plant code>"
export F312_GATEWAY="<actual gateway code>"
export F312_STATION="<actual station code>"

# Phase 1 — BEFORE delivery: actual signed material, no network or local writes
bash scripts/run_factory_f312_acceptance.sh verify

# Phase 2 — DURABLE delivery: existing F3.11, using an approved TLS endpoint
"$HOME/bin/agiparel-scanrelay" enqueue --dir "$F312_DIR" --file "$F312_FILE"
"$HOME/bin/agiparel-scanrelay" flush --dir "$F312_DIR" \
  --endpoint https://YOUR-APPROVED-INGRESS.example/api/v1/wip/production/scans \
  --max-age 12m --batch 50
"$HOME/bin/agiparel-scanrelay" status --dir "$F312_DIR"

# Phase 3 — independent PostgreSQL evidence under tenant RLS, **no writes**
bash scripts/run_factory_f312_acceptance.sh audit
```

The wrapper uses `python3` only to parse the relay's own JSON report safely; it uses the installed Docker Compose PostgreSQL 16 container and assumes access to the development/staging database through `compose/docker-compose.dev.yml`. Never run this against a live production database as part of casual testing. Adapt connection policy and obtain written operational approval before any production commissioning exercise. Do not paste secrets or private keys into terminal history, CI logs or this chat. The **public** Ed25519 key is not secret.

An expired queued scan cannot be resurrected: quarantine is a mandatory failure outcome; new hardware observation and/or F3.10 supervised recovery must follow. A valid replay of an accepted signed event should retain the **same** scan UUID and be reported as a replay, never count as another physical scan.

## Witnessed physical commissioning checklist — to be completed on site

| Test | Expected result | Witnessed? |
|---|---|---|
| Real RFID read and independent barcode confirmation | Reader identifies intended tag/part; scanner signer produces authentic scope-bound envelope | NOT TESTED |
| Enrolled key and plant/station | F3.12 verify and live DB audit pass for provisioned gateway only | NOT TESTED |
| Network unplug before flush | Durable pending event remains, no server ACK | NOT TESTED |
| Restore network before acceptance deadline | Original signed bytes are delivered, accepted receipt and one immutable DB row | NOT TESTED |
| Repeat same accepted envelope | F3.3 reports a replay with **same** scan ID, no duplicate DB row | NOT TESTED |
| Reuse event ID with altered payload, disabled or wrong plant key | Server rejects; no custody mutation | NOT TESTED |
| Outage beyond max admission age | Event quarantined; no backdating or false receipt | NOT TESTED |
| Crash/power loss during inflight send | Restart resubmits via F3.11; same accepted row after deduplication | NOT TESTED |
| Full disk, clock skew, TLS failure | Explicit error, no accepted receipt or fabricated physical observation | NOT TESTED |
| Real WIP DEPART and ARRIVE, separate authenticated workers | F3.3 movement sequence only through signed worker assertions and approved route | NOT TESTED |
| Open F3.10 exception / replace tag / independent supervisor closure | Open hold blocks movement and QC; new physical scan plus valid binding required for closure | NOT TESTED |
| Cross-tenant and plant isolation | Other tenant/plant observations inaccessible; signed scope not substitutable | NOT TESTED |

A positive F3.12 SQL result is **SIGNED-CHAIN DATABASE RECONCILIATION ONLY**. Physical-reader certification requires documented equipment identity/firmware, calibrated equipment as applicable, network and RF field trials, signed test-witness record, date/time, failure evidence, independent reviewer and approved plant release; these human records are **not** generated by this tooling.
